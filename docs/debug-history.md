## Bug #7 — Invalid package.json Generated by AI

### Error
ValueError: Failed to parse generated package.json:
Expecting property name enclosed in double quotes
(line 14 col 5)

### What happened
During Version 2 backend generation testing, the AI generated an invalid package.json file. The existing file_writer correctly detected the invalid JSON and stopped project generation.

### Root Cause
The LLM was allowed to generate package.json content directly, which resulted in invalid JSON syntax.

### Fix
package.json should be generated deterministically using Python json.dumps() instead of relying on raw LLM output. Validate package.json with Python's JSON parser before writing it.

### Status
Found during testing. Fix is currently being implemented.


## Recent Frontend Generation and Build Issues

### Bug: Invalid React entry file generated

**Error:** TypeScript compilation failed because explanatory natural-language text was inserted directly into `src/main.tsx`.

**Cause:** The frontend generator returned explanation text together with the generated TypeScript source.

**Fix:** Updated the frontend generator to produce deterministic React + TypeScript entry code and clean generated output.

**Validation:** Regenerated the frontend and verified the generated `main.tsx` contains valid React code.

---

### Bug: Vue code generated in React project

**Error:** `main.tsx` contained `defineComponent` and imported Vue even though the project dependencies were React.

**Cause:** The generated frontend output was not consistently constrained to the selected React stack.

**Fix:** Updated the frontend generator to use deterministic React + TypeScript templates.

**Validation:** Generated `main.tsx` using `createRoot` from `react-dom/client`.

---

### Bug: Missing TypeScript configuration

**Error:** `TS5083: Cannot read file 'tsconfig.json'`.

**Cause:** `package.json` used `tsc -b`, but the generated frontend did not contain the required TypeScript configuration files.

**Fix:** Added deterministic generation of:

* `tsconfig.json`
* `tsconfig.app.json`
* `tsconfig.node.json`
* `vite.config.ts`

**Validation:** Regenerated the frontend configuration files.

---

### Bug: Missing Node type definitions

**Error:** `TS2688: Cannot find type definition file for 'node'`.

**Cause:** `tsconfig.node.json` referenced Node types but `@types/node` was missing from `package.json`.

**Fix:** Added `@types/node` to the generated frontend `devDependencies`.

**Validation:** Regenerated the project and verified the generated package configuration.

---

### Bug: TypeScript project reference configuration

**Error:** `TS6306: Referenced project tsconfig.node.json must have setting "composite": true`.

**Cause:** The referenced TypeScript configuration was not marked as a composite project.

**Fix:** Added `"composite": true` to the generated `tsconfig.node.json`.

**Validation:** Regenerated the configuration and verified the TypeScript configuration files.

---

### Bug: Invalid Doctors component generated

**Error:** `src/Doctors.tsx` produced approximately 30 TypeScript syntax errors, including `TS1005`, `TS1434`, and `TS1435`.

**Cause:** Natural-language explanation text was inserted into the TypeScript source instead of being returned only as an explanation.

**Fix:** Updated the frontend generator with deterministic file-specific React component generation and output cleaning.

**Validation:** Regenerated the frontend and confirmed `npm run build` succeeded.

---

### Bug: Missing styles.css

**Error:** Vite reported `Failed to resolve import "./styles.css" from "src/main.tsx"`.

**Cause:** `main.tsx` imported the stylesheet, but the stylesheet was not consistently created in the generated frontend.

**Fix:** Updated the frontend generator to generate and write the reusable `styles.css` file together with the frontend components.

**Validation:** Regenerated the frontend and verified the stylesheet is included in the generated project.

---

### Bug: Frontend generator method signature mismatch

**Error:** `TypeError: FrontendGenerator.generate_dashboard_tsx() takes 1 positional argument but 3 were given`.

**Cause:** Duplicate legacy component-generation methods conflicted with the newer deterministic frontend generator implementation.

**Fix:** Removed the duplicate legacy methods and retained the new deterministic generic frontend generation flow.

**Validation:** Ran:

`python -m app.code_generator.test_generation`

The generator test completed successfully.

## Bug: OAuth2PasswordBearer Not Defined in Generated Backend

### Status
Fixed

### Where
Generated Hospital Management System backend:

`generated_projects/hospital_management/backend/routers/routes.py`

### Error
When starting the generated FastAPI backend with:

`python -m uvicorn main:app --reload --port 8001`

the application initially failed with:

`NameError: name 'OAuth2PasswordBearer' is not defined`

### Cause
The generated `routes.py` used `OAuth2PasswordBearer`:

`oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/login")`

but the required FastAPI security import was missing.

### Fix
Added the required import:

`from fastapi.security import OAuth2PasswordBearer`

### Verification
After the fix, the FastAPI backend started successfully and the application completed startup.

The generated backend was accessible on:

`http://127.0.0.1:8001`

FastAPI documentation was also available through `/docs`.

### Impact
The bug prevented the generated FastAPI application from starting.

### Result
Fixed successfully. Existing project functionality was preserved.
